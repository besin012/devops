## 필수와 선택 구분

- 필수: 이미지 생성 과정 + 나만의 방명록 브라우저 캡처 + 레지스트리 한 곳 푸시 + 각 과정의 스크린샷과 짧은 설명.
- 보너스: Dockerfile 명령어 순서가 레이어 캐시에 미치는 영향을 한 장으로 핵심 키워드와 설명 포함하여 정리 (0.5점).
- GitHub 소스 푸시, 친구 이미지 실행, 멀티스테이지 비교는 교안 실습 내용이다. 과제 안내의 필수 제출 항목으로 별도 명시되지는 않았지만 자료로 추가 가능.
- Docker Hub와 GHCR 모두 업로드할 필요 없다. 이번에는 GHCR 사용.
- 친구 주소를 받지 않아 공개 수업 예제로 대체했다. 캡처를 '친구 이미지 실행'으로 표시하지 않는다.
- 현재 레지스트리 이미지는 arm64만 실행 플랫폼으로 확인됨. 'amd64/arm64 모두 지원'이라고 적지 않는다.

## 이전에 만든 PPT를 사용할 때

기존 PPT의 Private 설명과 캡처는 현재 상태와 다르다. 5장의 이미지를 `registry-public.png`로 바꾸고 Public이라고 수정한다.
기존 4장의 명령어 텍스트만으로는 '각 과정 스크린샷' 요구를 충분히 보여주기 어려우므로 실제 `build-log.png`를 추가한다.
방명록 캡처는 글이 등록된 `guestbook-blue-complete.png`로 바꿀 수 있다.
원문 로그가 함께 있으므로 터미널에서 cat으로 열어 직접 캡처해도 된다. build-log/cache-log PNG는 Terminal 앱 사진이 아닌 실제 셸 로그의 브라우저 표시 캡처이다.
